## Summary

The walking skeleton could create two overlapping bookings for the same room:
search already excluded busy rooms, but the create path never compared the
requested window with existing bookings. This PR adds the missing rule. A booking
whose half-open window overlaps an existing booking for the same room is rejected
with HTTP 409 and error code `overlap`, and no record is created. Adjacent windows
(for example 11:00–12:00 after 10:00–11:00) remain allowed.

## Linked requirement and acceptance criteria

FR-03: given an existing booking 10:00–11:00.

- [x] Request 10:30–11:30 for the same room returns 409 `overlap`, no record created.
- [x] Request 11:00–12:00 for the same room returns 201 (adjacent, no overlap).
- [x] Same window in a different room is unaffected (per-room rule).
- [x] Full suite passes with no regressions.
